Informe Técnico de Diseño Arquitectónico Resiliente

Plataforma SaaS de Transporte Escolar Multiinstitucional

Autor: Principal Software Architect & Senior Technical Lead

Fecha: Octubre 2026

Marco Legal & Geográfico: Ecuador / LOPDP (Ley Orgánica de Protección de Datos Personales)

Propósito: Resolver de forma demostrable las 4 tensiones técnicas operativas (Offline, Ahorro de Megas Prepago, Timbre de Proximidad y Privacidad de Menores) antes de iniciar la construcción del código.

1. Resumen Ejecutivo del Diseño

El éxito de una aplicación de transporte escolar en América Latina no se decide en condiciones ideales de laboratorio con conexión de fibra óptica 5G; se decide en las periferias urbanas y valles, donde:

  1. La señal celular de las operadoras (Claro, Movistar, Tuenti) sufre micro-cortes o desvanecimientos repentinos.
  2. Los conductores y muchos padres de familia recargan paquetes prepago de datos móviles limitados ($1 o $2 por 200 MB – 500 MB).
  3. Los conductores no pueden distraerse operando interfaces complejas mientras conducen.
  4. La impuntualidad de los representantes al salir a la parada genera un "efecto dominó" de retrasos en toda la ruta.
  5. Los datos de ubicación y domicilios de los niños están amparados por legislaciones estrictas de protección de datos (LOPDP Ecuador, Art. 25).

2. Resolución de la Tensión 1: Modo Offline y Resiliencia de Datos

¿Cómo garantizar la continuidad operativa del conductor sin internet y mantener informados a los padres?

2.1. Arquitectura Local Offline-First del Conductor (IndexedDB + Cola Transaccional)

El dispositivo del conductor no realiza peticiones HTTP directas y bloqueantes para sus operaciones de ruta. En su lugar, implementa el patrón Local-First with Outbox Pattern:

flowchart TD DriverUI["Interfaz del Conductor (1 Toque)"] --> LocalWrite["Escritura Inmediata en Base Local (IndexedDB)"] LocalWrite --> OptimisticUI["Actualización Visual Inmediata (0 ms latencia)"] LocalWrite --> OutboxQueue["Encolado en 'sync_queue' (IndexedDB)"] OutboxQueue --> NetWatcher{"Monitor de Red (NetworkWatcher)"} NetWatcher -- "Conectado (Online)" --> Dispatcher["Sincronizador en Segundo Plano"] NetWatcher -- "Sin Conexión (Offline)" --> Standby["Modo Espera & Badge 'X pendientes'"] Dispatcher --> SupabaseBatch["Envío en Lote a Supabase RPC ('sync_trip_events')"] SupabaseBatch -- "Éxito (200 OK)" --> PurgeLocal["Eliminación de la cola local"] SupabaseBatch -- "Error / Timeout" --> BackoffRetry["Reintento con Retroceso Exponencial"]

Estructura de la Base de Datos Local (IndexedDB - Store: transporte_local_db):

  • trip_manifest: Padrón precargado del viaje actual (estudiantes, paradas, orden, direcciones de referencia y teléfonos de emergencia). Permite operar 100% desconectado.
  • attendance_records: Estado actual de cada estudiante (pending, boarded, dropped_off, absent).
  • sync_queue: Registro de eventos pendientes de envío al servidor con marcas de tiempo originales (client_timestamp).

2.2. Manejo de Conflictos y Transacciones Idempotentes

Para evitar duplicados si la conexión se corta a mitad de una petición HTTP, el backend expone un procedimiento almacenado PostgreSQL idempotente:

  • Cada evento enviado incluye un client_event_id (UUID).
  • Si el servidor ya procesó ese UUID, responde HTTP 200 { status: 'already_applied' } sin duplicar registros.
  • La hora registrada para la asistencia es siempre client_timestamp (la hora real en que el niño subió al bus), evitando que se registre la hora en que el conductor recuperó la señal 15 minutos más tarde.

2.3. Experiencia de Usuario para los Padres durante la Desconexión

Si el bus pierde cobertura durante el recorrido, el marcador del bus en el mapa entra en modo "Atenuado / Semitransparente" con el siguiente indicador:

📡 Estado del Transporte

El transporte se encuentra en una zona con baja señal celular. Última parada registrada: Los Pinos (07:14 AM). La ruta continúa su curso normal.

4.2. Generación del Timbre Sonoro con Cero Descargas (Web Audio API)

Para no consumir datos móviles descargando audios MP3 en cada parada, el timbre se genera matemáticamente en el navegador con la Web Audio API:

export function playSchoolChime(): void {
  try {
    const audioCtx = new (window.AudioContext || (window as any).webkitAudioContext)();
    const now = audioCtx.currentTime;
    
    // Tono 1: Campana alta (880 Hz - Nota La5)
    const osc1 = audioCtx.createOscillator();
    const gain1 = audioCtx.createGain();
    osc1.type = 'sine';
    osc1.frequency.setValueAtTime(880, now);
    gain1.gain.setValueAtTime(0.3, now);
    gain1.gain.exponentialRampToValueAtTime(0.001, now + 0.8);
    osc1.connect(gain1);
    gain1.connect(audioCtx.destination);
    
    // Tono 2: Resonancia cálida (587.33 Hz - Nota Re5 con delay de 150ms)
    const osc2 = audioCtx.createOscillator();
    const gain2 = audioCtx.createGain();
    osc2.type = 'triangle';
    osc2.frequency.setValueAtTime(587.33, now + 0.15);
    gain2.gain.setValueAtTime(0.4, now + 0.15);
    gain2.gain.exponentialRampToValueAtTime(0.001, now + 1.2);
    osc2.connect(gain2);
    gain2.connect(audioCtx.destination);

    osc1.start(now);
    osc1.stop(now + 0.8);
    osc2.start(now + 0.15);
    osc2.stop(now + 1.2);
  } catch (e) {
    console.warn('Audio no permitido o no soportado', e);
  }
}

4.3. Protocolo UX Anti-Impuntualidad en 3 Fases

  • Fase 1 (Pre-aviso a ~1.2 km / 6 min): Notificación silenciosa indicando proximidad al sector.
  • Fase 2 (Alerta Activa y Timbre a ~500 m / 3 min): Timbre sonoro + cuenta regresiva dinámica en pantalla amarilla con botón gigante: [ 🟢 ¡YA ESTAMOS EN LA PARADA! ].
  • Fase 3 (Confirmación en el Bus): Al presionar el botón, la tarjeta del alumno en la pantalla del conductor destella en verde. Si no lo hace y el bus llega, corre un temporizador de cortesía de 60s antes de habilitar el botón de 1 toque: "Reportar Ausencia".

7. Conclusión

Garantías del Diseño

Este informe técnico demuestra que la plataforma está arquitectónicamente preparada para operar sin interrupciones ante fallas de cobertura celular, con un consumo que no agotará los saldos prepago de los usuarios, resolviendo la impuntualidad en las paradas con timbres sonoros sin descargas y garantizando el cumplimiento pleno de la normativa de protección de datos de menores.
